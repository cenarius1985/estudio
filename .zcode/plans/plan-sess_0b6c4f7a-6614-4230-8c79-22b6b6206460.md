# Plataforma "Estudio Doctorado" — Plan completo

## Objetivo
Plataforma personal dockerizada en `E:\GitHub\MRI\estudio-doctorado` (hoy vacía) que indexa todo el material de la tesis MRI-UTE, envía un **tip diario por correo (Brevo)**, permite **hacer preguntas web con respuestas 100% fieles a los documentos**, ofrece **flashcards/cuestionarios/simulacro** (estilo Astra AI) y un **panel de administración** con historial de tips anti-duplicados.

## Decisiones ya tomadas (basadas en exploración)
- **Credenciales Brevo**: se copian los 5 valores `SMTP_HOST/PORT/USER/PASS/FROM` de `E:\GitHub\Ministerio\reportesDiariosGes\.env` (relay `smtp-relay.brevo.com:587`) al `.env` nuevo. - **Bonsai (LLM local)**: se replica el servicio de `E:\GitHub\whispertext` (rama `gpu` activa): llama-server PrismML + Ternary-Bonsai-2-27B PTQ1_0, API OpenAI-compatible, perfil docker `gpu`. Cliente fail-soft copiado/adaptado de `whispertext/backend/wispertext/worker/bonsai.py`. **Riesgo conocido**: el GGUF en disco pesa 1.24 GB y el README dice ~5.7 GB → el coordinador verifica tamaño y re-descarga si está incompleto/truncado.
- **Patrón de proyecto**: FastAPI + ARQ (worker con cola Redis) + PostgreSQL + Next.js + `coordinador.py` instalador, igual que whispertext.
- **Anti-alucinación (tu punto)**: NO RAG vectorial puro. Recuperación **híbrida**: párrafos en pgvector + BM25 (Postgres FTS, español/inglés) fusionados con RRF + **grafo de conocimiento ligero** (entidades/conceptos de la tesis: UTE, T2*, fat-water, SNR… con relaciones extraídas por Bonsai en la ingesta) para expandir párrafos relacionados en preguntas multi-salto. La generación es **con citas estrictas**: cada afirmación cita [archivo, pág/párrafo]; sin respaldo suficiente → "No encontré eso en tus documentos".
- **Documentación**: PRD antes de implementar + runbook final, en el vault DATACEF `G:\Mi unidad\DATACEF\DOCUMENTACION-PROYECTOS\ESTUDIO-DOCTORADO-DATACEF` (estilo skill minsal: kebab-case numérico, Estado 📝/✅, escrito directo como .md).

## Ingesta (montura read-only de `E:\GitHub\MRI\Proyecto-Tesis`)
Formatos: **PDF** (PyMuPDF; páginas sin texto → rasterizar + Tesseract spa+eng), **LaTeX .tex** (limpieza conservando matemáticas; tesis por capítulos 1-9 + anexos), **TXT/MD/CSV**, **Word .docx** (python-docx), **Excel .xlsx** (openpyxl → tabla markdown por hoja), **imágenes .png/.jpg/.tif** (Tesseract OCR — figuras MRI/capturas), **.ipynb** (nbformat: markdown+código+salidas).
- Fuentes: `MRI-UTE PROYECTO DE TESIS`, `paper-mri-us`, `defensa_tesis_doctoral`, `RESULTADOS-MRI` (documentos y figuras; **excluido** `Tensorflowmri` 54GB de datos crudos).
- Chunking por párrafos ~1000 tokens, overlap 15%, metadatos (ruta, tipo, página/hoja/capítulo). Hash SHA256 por archivo → ingesta **incremental** (solo reindexa lo cambiado).
- Embeddings: `fastembed` (ONNX, CPU) con modelo multilingüe `intfloat/multilingual-e5-large` (tesis ES + papers EN). Prefijos query:/passage:.
- Grafo: en la ingesta, Bonsai extrae entidades/relaciones por documento → tablas `nodos`/`aristas` (co-ocurrencia + extracción), usadas para expandir contexto en el chat.

## Esquema de datos (Postgres + pgvector)
`documents(id, ruta, tipo, hash, estado, chunks_n, indexado_en)` · `chunks(id, document_id, n, texto, pagina, embedding vector(1024), tsv tsvector)` · `nodos(id, nombre, tipo)` / `aristas(nodo_a, nodo_b, relacion, chunk_id)` · `tips(id, fecha, titulo, cuerpo_html, cuerpo_texto, embedding vector(1024), estado, duplicado_de, creado_en)` · `tips_envios(tip_id, email, estado, error, enviado_en)` · `decks`/`flashcards`/`flashcard_reviews` (SM-2 lite) · `quizzes`/`preguntas`/`intentos` · `conversaciones`/`mensajes` · `settings(k,v)`.

## Tip diario — pipeline con dedupe (tu requisito exacto)
1. Cron ARQ a `TIPS_HORA` (default 07:30). **Idempotente**: si hoy ya se generó/envió, no reprocesa nada.
2. Elige párrafo/tema **menos cubierto** (tabla de cobertura chunks↔tips).
3. Recuperación híbrida del contexto → Bonsai genera tip (título + 150-250 palabras + 2-3 citas archivo/página).
4. **Dedupe**: embed del tip → coseno vs historial; si sim ≥ umbral (0.90 configurable) → marca duplicado y **reutiliza el tip ya existente desde la BD sin reprocesar**; hasta 3 reintentos con otro tema.
5. Envío por Brevo + log en `tips_envios` (ok/error, patrón EnvioLog de reportesDiariosGes).
6. Panel: "Enviar ahora" (fuerza job), "Reenviar" tip histórico → envía el HTML almacenado, **cero reprocesamiento**.
Extra Astra: algunos días el tip es una "flashcard del día" generada del mismo pool.

## Chat web fiel + estudio (fase Astra incluida)
- `/api/chat` SSE: pregunta → embeddings + BM25 + RRF + expansión por grafo → Bonsai con prompt de citas estrictas → streaming con citas clicables al documento/página. Historial de conversaciones en BD.
- **Flashcards**: decks por documento/tema generados por Bonsai (frente/verso + cita), repaso con repetición espaciada (SM-2 lite).
- **Cuestionarios**: N preguntas de opción múltiple + explicación citada; corrección inmediata.
- **Simulacro**: examen cronometrado con preguntas mixtas de todos los temas, resultado y repaso de errores.

## Panel (Next.js 14, login simple con `ADMIN_PASSWORD`)
Documentos (upload + fuentes montadas, estado de ingesta, reindexar, borrar) · Tips (historial calendario, preview HTML, Enviar ahora/Reenviar, duplicados marcados) · Chat · Estudio (flashcards/quiz/simulacro) · Ajustes (hora, destinatario, umbral dedupe, test de SMTP sin enviar — tipo `probar_correo.py`, estado de Bonsai) · Stats (docs por tipo, chunks, cobertura, tips enviados).
